# G2 双臂 IK 末端甩动问题 — 完整报告

> 适用范围：`DualArmKinematics`（`src/lerobot/model/kinematics.py`）及其在 G2
> rollout / record / replay / reset 中的使用。本报告记录了 pi0.5 微调模型部署时
> 出现的"末端横向甩出"问题的定位、根因与修复。

## 1. 问题（Symptom）

使用 pi0.5 微调模型部署 G2 双臂时，**手臂去拿较远处物体的瞬间，末端会突然快速、大幅地横向甩出去**。

关键观察（用户现场）：

- 甩动表现为**末端（end-effector）本身发生大幅位移**，飞到一个非预期的远处位置；
- **不是**"某个关节大动、末端几乎不动"的零空间肘部翻转（elbow-flip）。

策略输出的是 `arm_base_link` 参考系下的**绝对 EE 位姿**，经 `InverseKinematicsEEToJoints`
→ `DualArmKinematics.inverse_kinematics_dual`（placo）解算成关节角后下发。

## 2. 复现与量化

用 FK 生成可达 EE 目标、再用 IK 反解的方式离线复现（探针脚本 `ik_limit_test.py`）。
核心指标：给定一个**小的** EE 命令步长（2cm），测量 IK 解出的关节经 FK 后**末端实际移动了多远**。

| 配置 | 区域 | 命令步长 | 末端实际移动 max | 过冲 max |
|---|---|---|---|---|
| 旧（manip 开 / 无 reg / iter=3） | 远伸 | 2cm | 2.36cm | 0.36cm |
| 旧 iter=30 | 远伸 | 2cm | 4.51cm | 2.51cm |
| 旧（manip 开 / 无 reg / iter=3） | 折叠近限位 | 2cm | 7.65cm | 5.65cm |
| **旧 iter=30** | 折叠近限位 | 2cm | **33.55cm** | **31.55cm** |

→ **一个 2cm 的小命令，旧 IK 让末端实际飞出最多 33cm**，这就是现场看到的"甩出去"。
注意末端过冲会**直接体现在 pos 误差**上（`|FK(IK解) − 命令目标|`），旧配置在边界处 pos 误差 max 达 0.34m。

## 3. 根因（Root Cause）

定位过程中发现**四个叠加问题**，按重要性排序：

### 3.1 速度型 IK 在奇异点处病态、且无阻尼（主因）

placo 的 `KinematicsSolver` 是**速度型/微分 IK**（每次 `solve` 沿任务梯度走一小步 `dt`）。
当手臂接近**伸展极限/腕部奇异点**（拿远物时正是如此），雅可比病态，单步关节速度爆炸式增大；
迭代循环把这些病态速度**积分**，末端就顺着病态方向冲过头、横甩出去。**迭代越多越严重**
（远伸 it3→it30：末端实际位移 7.6cm→33cm 是同一机理在折叠区的体现）。当前 `max_iterations=3`
反而歪打正着压住了一部分伤害。

### 3.2 阻尼参数是死代码

代码里 `self.solver.eps = eps` 和 `self.solver.damping = 0.6` —— **placo 的
`KinematicsSolver` 根本没有 `eps`/`damping` 属性**，这两行只是给 Python 对象挂了永不被读取的
死属性。也就是说**求解器一直在"零阻尼"下运行**，3.1 的病态速度完全没有被抑制。
（placo 中真正等价于阻尼的是 `add_regularization_task(w)`。）

### 3.3 manipulability 任务造成稳态精度偏置

`add_manipulability_task(..., 1e-3)` 追求"可操作性最大化"（远离奇异），这是个**次级目标，
会把解从命令的 EE 目标上拽开**，导致收敛在一个稳态偏置点（实测**精度天花板 ~3.5mm，
加多少迭代都压不下去**），并在边界处放大末端偏离。它本意是抗奇异，但代价是精度与跟踪偏置。

### 3.4 关节限位被关闭 + 事后裁剪

`enable_joint_limits(False)` + 解后 `_clip_joint_positions_deg` 对各关节独立裁剪。
经验证：在**起点关节读数略微越界**（真机传感器噪声 + 0.1° 安全余量）时，开硬限位会让 QP
不可行、收敛率骤降（这正是原作者当初关掉限位的真实原因）。但关掉 + 独立裁剪在不可达时会破坏
EE 对应关系。实测在修复 3.1–3.3 后，**IK 结果自然落在限位内（越界率 0.0%）**，裁剪不再触发，
此问题随之消失，故保持限位关闭即可。

> 补充：坐标系为 `arm_base_link`（双臂安装根节点，位于躯干 `body_link5` 上方 0.3085m，
> 约上胸/肩高）。手臂最大臂展 ~93cm；"拿远物"对应末端距 `arm_base_link` 约 75–92cm 的伸展区，
> 也正是伸展奇异最严重、3.1 最易发作的区域。

## 4. 解决方法（Solution）

核心思路：**用速度正则（Tikhonov / 阻尼最小二乘 DLS）取代 manipulability 任务**，
作为零空间稳定器。两者都能抗奇异/稳住 7-DOF 冗余，但：

- **manipulability**：有稳态牵引偏置（拽离目标）→ 精度差；
- **regularization**：只惩罚关节速度，收敛时速度→0、代价→0，**无稳态偏置**，
  同时在过程中阻尼掉 3.1 的病态速度 → 既稳又准。

### 4.1 代码改动

`src/lerobot/model/kinematics.py`（`DualArmKinematics`）：

1. **manipulability 任务默认关闭**（新增 `manipulability_weight=0.0`，>0 才创建）；
2. **新增速度正则任务** `self.solver.add_regularization_task(regularization_weight)`
   （新增 `regularization_weight=1e-3`）；
3. **删除死代码** `self.solver.eps` / `self.solver.damping`；
4. 默认值更新：`max_iterations 3→10`、`dt 1e-2→5e-2`。

`src/lerobot/scripts/lerobot_rollout_g2.py`（`RolloutConfigG2`）暴露可调旋钮并设定新默认：

| 字段 | 旧值 | 新值 | 作用 |
|---|---|---|---|
| `ik_position_weight` | 1.0 | 1.0 | 位置任务权重 |
| `ik_orientation_weight` | 1e-2 | **0.2** | 姿态任务权重（拉高，姿态进可达区亚度级） |
| `ik_regularization_weight` | —（死代码 0.6） | **1e-3** | DLS 阻尼 / 零空间稳定器（防甩，必需） |
| `ik_manipulability_weight` | 1e-3 | **0.0** | 关闭（>0 会劣化精度与过冲） |
| `ik_max_iterations` | 3 | **10** | 迭代预算 |
| `ik_dt` | 1e-2 | **5e-2** | 积分步长 |

> `record` / `replay` / `reset` 路径通过同一 `DualArmKinematics` 默认值自动受益。

### 4.2 调参指南

- **防甩动**：`ik_regularization_weight` 是关键旋钮。**不可设 0**（设 0 时伸展区会
  灾难性失稳，pos 可达 97mm、末端飞出 ~1m）。`1e-3` 干净；电机怕急动想要更柔顺的关节运动时
  调到 `3e-3`（代价：位置 ~2mm→~2.8mm）。
- **姿态精度**：`ik_orientation_weight`。`0.2` 时可达区 ori max ≈0.34°；若策略姿态目标不可信，
  可降回低值让位置主导。
- **不要开 manipulability**：任何 `>0` 都同时劣化位置和过冲。

## 5. 验证数据（修复后）

推荐配置 `posW=1 / oriW=0.2 / reg=1e-3 / manip=0 / iter=10 / dt=0.05`，2cm 命令步长：

| 区域（距 arm_base_link） | pos mean / max | ori max | 末端过冲 max | IK 越界率 |
|---|---|---|---|---|
| 远伸 ~75–92cm（拿远物） | 1.72mm / 19.4mm | 0.34° | **0.00cm** | 0.0% |
| 折叠近限位 ~41cm | 0.16mm / 11.5mm | —（见下） | 0.38cm | 0.0% |

对比修复前（边界末端过冲 max 31cm）→ **修复后过冲 ≈0，甩动消除**。

### 5.1 关于残余 max 误差（19mm）的分解

上表远伸区 `pos max=19.4mm` 看似不小，但需区分"IK 精度"与"目标可达性"。将目标分别构造为
**可能不可达**（当前位姿 + 2cm 随机笛卡尔步进）与**保证可达**（当前关节 + 小扰动后 FK）：

| 目标类型 | pos mean | p95 | max | >5mm 比例 | 其中欠程(undershoot)占比 |
|---|---|---|---|---|---|
| 2cm 笛卡尔步进（可能不可达） | 2.01mm | 12.87mm | 18.8mm | 15.1% | **100%** |
| **构造为可达** | **0.17mm** | **0.54mm** | **0.8mm** | **0.0%** | — |

结论：

1. **对真正可达的目标，IK 是亚毫米的**（mean 0.17mm、max 0.8mm）；
2. **远伸区的大误差 100% 来自"够不到"**——手臂已伸到 86–92cm（逼近 93cm 臂展），约 15% 的随机
   步进把目标推到可达范围外，IK 尽力伸到边界停住，残余误差 = 到不可达点的距离，非求解器缺陷；
3. **这些"够不到"全是欠程（undershoot），不是过冲**——即使策略命令超出臂展的目标，
   末端也只会停在边界、不会再甩出去（旧 IK 同样情况过冲 31cm）。

因此误差应这样读：远伸 mean 1.72mm 含约 15% 够不到的拖累，纯可达目标约 0.17mm；
max 19mm 是够不到点的剩余距离。规避手段只能是不让目标落在臂展极限外。

## 5.2 连续轨迹稳定性测试（近→远）

用一条从胸前可达近点、沿径向向外掃到远超臂展的连续轨迹（起点 FK 构造保证可达，
每步 1.5cm，IK 以上一帧关节为初值，模拟真机跟随）测默认逆解稳定性：

| 区间（距 arm_base_link） | pos_err | EE 单步 | 行为 |
|---|---|---|---|
| 可达（84→93cm） | ≤1.24mm | ~1.5cm（跟手） | ✅ 亚毫米、平滑 |
| 略超出可达（≤~30cm 外，95→126cm） | 16→336mm | 0.02–1.6cm | ✅ 优雅欠程：末端停边界不甩 |
| 远超可达（>~35cm 外，≥128cm） | →1.5m | 最高 112cm | ❌ IK 失稳、末端飞 ~1m |

→ reg 修复治住了**奇异点附近**的甩动；但当目标**离谱地远**（本例超臂展 35cm 以上）时，
速度型 IK 持续承受巨大任务误差，最终关节饱和翻滚、末端被甩出。该残余失效**无法**靠 reg 调参
（非单调）或关节速率上限消除——后者在臂展奇异点处因长力臂放大，关节限 10°/帧时末端仍大幅摆。

### 远超可达护栏：不可达则保持（已实现）

采用的护栏是**解后可达性判据 + 保持**，而非预先的球面钳制：在 `inverse_kinematics_dual`
求解后，用 FK 复算到达位置误差，**误差 > 阈值即判为不可达，该臂改为保持当前关节**（不下发
发散/裁剪后的解）。这一招同时覆盖"略超出"和"远超出"——因为远超时的发散解 FK 误差巨大，
同样被拦下。

阈值取 **5mm**：可达误差上限仅 ~1.2mm（4× 余量，0% 误冻结），不可达误差 >16mm，空档极大、
无抖动。实现：

- `DualArmKinematics.inverse_kinematics_dual(..., hold_on_unreachable_pos_m=None)`：
  新增可选判据，`None` 时不启用（record/replay/reset 不受影响）；
- `InverseKinematicsEEToJoints.ee_unreachable_hold_threshold_m = 5e-3`：rollout processor
  默认启用，传入上述参数。

验证（近→远轨迹，命令 84cm 掃到 173cm）：保持关闭时末端最大单步 112cm（甩飞）；
**保持开启后最大单步 1.50cm**，越过 93cm 臂展边界后自动保持、60 帧中保持 54 帧，
末端干净停在边界——近、边界、远三区间全部稳定，且无需球面预钳制。

## 6. 已知限制

- **边界姿态饱和**：手臂伸到可达极限时，位置与姿态无法同时满足，**姿态误差饱和在 ~3°（max ~8°），
  与 IK 调参无关**（7-DOF 物理可达性极限）。唯一规避手段是不让目标点落到臂展极限附近。
- 本报告数据来自离线 FK/IK 探针（`ik_limit_test.py`，可删）。真机部署后建议用现有日志核对：
  在甩动帧对比 `[l/r] absolute EE delta pos_norm`（命令步长）与末端实际位移——
  若命令小、末端飞远即为本问题；若命令本身就大，则是策略/相对动作换算侧的问题，需在 EE 空间限速。
- 未改动单臂类 `RobotKinematics`（同样存在 `eps`/`damping` 死代码与 manipulability），
  因其用于其它机器人、不在 G2 路径上；如需统一可另行处理。
